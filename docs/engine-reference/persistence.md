# Resonite Persistence & Serialization

> Resonite serialization/persistence and type-migration reference (ILSpy-verified) — the DataTree/BSON save format, SaveControl, RefID to GUID remapping (why refs break on reload), DependencyHandling, save hooks, and the Old-name/FeatureUpgrade type-migration attributes.

### Serialization / persistence (save-load format)

The whole save graph is an in-memory `Elements.Core.DataTreeNode` tree (subtypes `DataTreeDictionary` {key→node}, `DataTreeList`, `DataTreeValue` wrapping an `IConvertible`), serialized to disk by `Elements.Core.DataTreeConverter` as **BSON** (it walks the tree through a `JsonWriter`/`JsonReader`). Files start with magic `"FrDT"` + an int version + a compression enum byte (`DataTreeConverter.WriteHeader`); `DataTreeConverter.Save(root, file, Compression)` picks the codec. `DataTreeSaver` writes `lz4bson` normally and `brson` (Brotli) when `UseHeavyCompression` (`DataTreeSaver.LOCAL_FORMAT="lz4bson"`, `HEAVY_FORMAT="brson"`, `.Format`). Read back via `DataTreeConverter.Load(file, ext)` / `LoadAuto(stream)` (also `FromRaw{BSON,LZ4BSON,BRSON,7zBSON}`, `ToRawJSON` for a JSON dump).

- **The serialized object tree** (`Slot.SaveObject` / `World.SaveWorld` → returns a `SavedGraph` struct wrapping the root `DataTreeDictionary`). Top-level keys: `"VersionNumber"` (engine version string), `"FeatureFlags"` (dict of `engine.FeatureFlags` `Feature→Version`, `SaveControl.StoreFeatureFlags`), `"Types"` (a `DataTreeList` of encoded type names — the per-object type index), `"TypeVersions"` (encoded-type→int data-version), `"Object"` (the saved root), and optionally `"Dependencies"` (full slots, `CollectAll`) or `"Assets"` (just the asset components, `CollectAssets`). `SaveControl.StoreTypeData` is called last so the type table reflects everything referenced.
- **What a Worker writes** (`Worker.Save`): a `DataTreeDictionary` with `"ID"` (this worker's `ReferenceID`, run through `SaveControl.SaveReference`) plus one entry per sync member. **Throws "Cannot save non-persistent objects"** if `!IsPersistent && !control.SaveNonPersistent`. For each member it checks `SaveMember(member, control)` then: if the member `IsPersistent` (or `SaveNonPersistent`) AND not flagged `syncMemberDontCopy`, the member is serialized inline under its name and `MemberSaved(member,node,control)` fires; **otherwise only an identity stub is written under `"<name>-ID"`** (the member's own `ReferenceID`, so cross-refs to it still resolve, but its value is dropped). `Version>0` registers the type's data-version.
- **`[NonPersistent]` / `IsPersistent`**: a member marked non-persistent is the `-ID`-only case above — its identity is preserved for reference targeting but its value is never saved. **Non-persistent != excluded from the graph**; it's value-omitted.
- **`PersistentSelf=false`**: handled at the object level in `Slot.SaveObject`. If the slot isn't persistent and you didn't pass `saveNonPersistent`, and `PersistentSelf` is also false, it **throws "Cannot save non-persistent objects"**; if `PersistentSelf` is true it temporarily re-parents the slot to `World.RootSlot` for the save and restores afterward. So a `PersistentSelf=false` transient slot is silently skipped by normal world saves (its children/components never enter the tree).
- **RefID remapping (why references break across graphs)**: nothing on disk uses session-local `RefID`s. `SaveControl.SaveReference` → `ReferenceToString` → `ReferenceTranslator.Fetch(local)` maps each local `RefID` to a **freshly allocated sequential GUID** (`Fetch` increments `_currentGUID` from a base, skipping collisions, and caches in `local2global`/`global2local`). On load, `LoadControl.AssociateReference` parses that GUID string and calls `ReferenceTranslator.Associate(newLocalRefID, globalGuid)`, wiring it to a **new** local id and replaying any queued `ISyncRef` `Request`s. **Consequence:** a saved ref only resolves if its target's GUID is in the *same* graph (or an `UnresolvedReferences`/translator carried across). The `ReferenceFilter` in `Slot.SaveObject` actively **nulls out any RefID whose target isn't inside the saved hierarchy/dependency set** (`DependencyHandling.BreakAll`/non-`CollectAll`) — this is the canonical reason refs go null after a partial save/paste. Each `SaveObject` call uses its own fresh `ReferenceTranslator` unless you pass one in.
- **`DependencyHandling` enum** (arg to `Slot.SaveObject`): `BreakAll` (no dependency collection; all external refs filtered to `RefID.Null`), `CollectAssets` (pull in asset providers + `Component.PreserveWithAssets` components into an `"Assets"` list, keep refs to them, force `SaveNonPersistent` for them), `CollectAll` (pull whole referenced slot hierarchies into `"Dependencies"`). `World.SaveWorld()` saves the world root directly (no `SaveObject` dependency dance) with the world's persistent `refTranslator` and the root's `UnresolvedReferences` component.
- **`UnresolvedReferences`** (component on `RootSlot`): a `SyncList` mapping that lets a world carry forward references whose targets were never resolved this session. When present, `SaveControl.ReferenceToString` routes through `unresolved.TranslateReference(refID)` first so the original external GUID is re-emitted verbatim instead of being reallocated — preserving links across save/load cycles.
- **Save hooks / ordering**: `Slot.RunOnSaving` recurses depth-first calling `Worker.OnSaving(SaveControl)` on the slot, then each component, then children — runs *before* `StartSaving`, so it's the place to stamp state into fields pre-serialize. `SaveControl.OnBeforeSaveStart`/`OnSaved` register callbacks bracketing the write. **`ComponentBase.OnWorldSaved()` is unrelated to this per-object path** — the base impl is a guard (`ShouldntExecute()`); it's the `IWorldEventReceiver.OnWorldSaved` world-level event (`World.WorldEvent.OnWorldSaved`) fired after a full world save, override it for "world was persisted" reactions, not for influencing the serialized bytes (use `OnSaving` for that).
- **Mod entry points**: to serialize, `slot.SaveObject(DependencyHandling.CollectAssets)` or `world.SaveWorld()` → `SavedGraph`; persist with a `DataTreeSaver(engine)` — `await saver.SaveLocally(graph, uri)` (writes a local-DB asset, returns the `local://` URL) or `EnsurePermanentStorage(graph)` (just ensures referenced assets are stored), set `UseHeavyCompression` for Brotli. To load, `slot.LoadObjectAsync(uri/record, assetsRoot, refTranslator, preserveRootTransform, skipHolder, typeFilter)` or the synchronous `Slot.LoadObject(DataTreeDictionary, record, …)`. For a raw tree without the engine, `DataTreeConverter.Save`/`Load` directly. Higher-level world flow lives in `Userspace.SaveWorld(world, record, …)` / `SaveWorldAuto`.
- **Load-side version tolerance**: `Worker.Load` reads `"ID"` then per member tries `name`, then `name+"-ID"` (identity-only), then `InitInfo.oldSyncMemberNames` aliases (renamed members) before giving up — and swallows per-member load exceptions with a `UniLog.Error`, so a single bad member won't abort the object.

### Type migration / versioning (load-time save upgrade)

The attributes that upgrade old saves into renamed/moved/refactored types live in **`Elements.Data.dll`** (16 types, all just attribute/data definitions — no logic). The matching/resolution logic lives in **`FrooxEngine.dll`** (`AssemblyTypeRegistry`, `GlobalTypeRegistry`, `TypeManager`, `WorkerInitializer`). Correction to the prior survey: **`[OldNamespace]` does exist** — as `Elements.Data.OldNamespaceAttribute` — it is simply absent from FrooxEngine.dll (where the survey looked).

**The attributes (all in `Elements.Data`, applied to your *current* type/field to declare its history):**
- **`[OldTypeName(name, oldAssembly=null)]`** (`OldTypeNameAttribute`, `AllowMultiple`) — type was renamed/moved. If `oldAssembly==null`, registered as a same-assembly moved type keyed by old full name; else registered cross-assembly. For generics, `AssemblyTypeRegistry.ProcessOldTypename` auto-appends the live ``` `N ``` arity suffix if you omitted it. **Inherited automatically by nested types**: an `[OldTypeName]` on a declaring type re-registers each nested type with the old prefix substituted (`ProcessMovedTypes`).
- **`[OldAssembly(oldAssembly)]`** (`OldAssemblyAttribute`, `AllowMultiple`) — type stayed same-named but moved assemblies; registers `(FullName, oldAssembly)→type`. Also inherited by nested types (`ProcessMovedTypes`).
- **`[OldTypeHash(long)]`** (`OldTypeHashAttribute`) — matches a *stored* type string by its **SpookyHash64** (`GlobalTypeRegistry.RegisterOldTypeHash` → `TryGetOldTypeByHash` does `name.SpookyHash64()` lookup). Only consulted on the **legacy** load path (`TypeManager.DecodeLegacyType`).
- **`[OldNonGenericDefault(typeof(Generic<…>))]`** (`OldNonGenericDefaultAttribute`) — when a type became generic; maps the old non-generic full name (everything before `` ` ``) to a specific closed/default generic type (`ProcessMovedTypes`).
- **`[OldTypeSpecialization(name, params Type[] genericArgs)]`** (`OldTypeSpecialization`, `AllowMultiple`) — declares an old name for a specific generic *specialization*. **Not consumed in FrooxEngine.dll**; it is read in `ProtoFlux.Nodes.Core.dll` / `ProtoFluxBindings.dll` (ProtoFlux node binding migration only).
- **`[OldName(...)]` / `[OldName(params string[])]`** (`OldName`, field-level, `AllowMultiple`) — a **sync member field** was renamed. `WorkerInitializer.Initialize(Type)` collects these into `WorkerInitInfo.oldSyncMemberNames` (current member name → list of old names) so the loader can match an old field name in a save to the new member. The current member name itself is the `[NameOverride]` value if present, else the field name with a trailing `_Field` stripped.
- **`[OldNameHash(long)]` / `(params long[])`** (`OldNameHash`, field-level) — hash form of `[OldName]`. **Defined but NOT consumed in FrooxEngine.dll** (`WorkerInitializer.Initialize` reads only `OldName`, not `OldNameHash`) — treat as inert in the current engine.
- **`[OldNamespace(ns)]`** (`OldNamespaceAttribute`, on class/interface) — single `Namespace` string. Defined in Elements.Data but **no consumer in any shipped DLL** (only string ref is in Elements.Data itself); appears legacy/unused — don't rely on it, prefer `[OldTypeName]` with the full old namespace-qualified name.

**Feature-upgrade (version-gated) replacement** — `FeatureUpgradeReplacement : TypeReplacement` (abstract base `TypeReplacement` exposes `NewType` / `ReplaceSource` / `ReplaceTarget`):
- Declared as a **type attribute**: `[FeatureUpgradeReplacement(featureFlag, version, typeof(NewType))]` or `(featureFlag, version, replaceSource, replaceTarget)` (string substring rename).
- `WorkerInitializer.Initialize(allTypes)` gathers these into `featureFlagReplacements`. On load, **`WorkerInitializer.ResolveReplacement(type, version, featureFlags)`** is the apply entrypoint: if `replacement.NeedsUpgrade(featureFlags)` (true when `featureFlags==null`, the flag is absent, or `storedVersion < replacement.Version`) it computes the new type via `TypeReplacement.GetNewType(inputType)` (extension in `Elements.Core.TypeHelper`) and **recurses** (chained upgrades). `GetNewType` either returns `NewType` (re-closed over the input's generic args if needed) or does `inputType.FullName.Replace(ReplaceSource→ReplaceTarget)` then `FindType`. Generic types are resolved by recursing into the definition and every generic argument.
- `FeatureUpgradeFlags` is just constants: `NET_CORE = "NetCore"`, `NET_CORE_VERSION` (the .NET-10 migration flag). Stored feature flags come from `SaveControl.StoreFeatureFlags(engine)` which dumps `engine.FeatureFlags` (each `FeatureFlag.Feature → .Version`) into the save; the loader compares the *stored* dict against the type's required `Version`.

**Data-model classification** (gates whether a type is even loadable): `[DataModelType]` (`DataModelTypeAttribute`, on class/struct/enum/interface/delegate) marks a serializable type; `[assembly: DataModelAssembly(DataModelAssemblyType.Core|UserspaceCore|Optional|Dependency)]` classifies the whole assembly; `[assembly: ExternalDataModelType(typeof(T))]` (`AllowMultiple`) pulls in a type from a non-data-model assembly. Only types in registered data-model assemblies are decodable (`TypeManager.GetDataModelType` warns "is not a data model assembly … cannot decode type" otherwise).

**Save side** (`FrooxEngine.SaveControl`): `RegisterTypeVersion(type, version)` records a per-type version (only if `version>0` and not already present); `StoreTypeData` writes each type via `World.Types.EncodeType` plus a `typeVersions` dict; `StoreFeatureFlags` writes the engine's feature flags. **Load side**: `TypeManager.DecodeType`/`DecodeLegacyType` resolve a stored `[assembly]typename` string → current `Type` via `AssemblyTypeRegistry.TryGetType(name, checkMovedTypes:true)` (checks `_typesByFullName` then the `_movedTypes` map built from the Old* attributes), falling back on the legacy path to `MapLegacyType` (hardcoded Quantity/SkyFrost remaps) and `GlobalTypeRegistry.TryGetOldTypeByHash`.

**What a mod author must do when adding/renaming a persisted type or field:**
- **New persisted type** → mark it `[DataModelType]` and ensure its assembly is a data-model assembly (RML mod types load via the engine's assembly registration; non-data-model deps need `[assembly: ExternalDataModelType(...)]`). Without this, saves can't decode it.
- **Rename/move a type** → keep the new type and add `[OldTypeName("Old.Full.Name")]` (and/or `[OldAssembly("OldAsm")]`); for generics either include the `` `N `` or let `ProcessOldTypename` append it. Hash-based `[OldTypeHash]` only helps on the legacy load path.
- **Make a previously-non-generic type generic** → add `[OldNonGenericDefault(typeof(MyType<DefaultArg>))]`.
- **Rename a sync member field** → add `[OldName("OldFieldName")]` (multiple allowed). Do **not** rely on `[OldNameHash]` or `[OldNamespace]` — neither is consumed by the current engine.
- **Version-gated refactor** (e.g. a .NET-Core migration) → `[FeatureUpgradeReplacement(FeatureUpgradeFlags.NET_CORE, FeatureUpgradeFlags.NET_CORE_VERSION, typeof(NewType))]`, and call `RegisterTypeVersion` if you need per-type version gating on save.
