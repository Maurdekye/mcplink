# Resonite Particles

> Resonite particle-system reference (PhotonDust, ILSpy-verified) — CPU multithreaded sim, emitters/modules/renderers, ParticleStyle, capacity/defaults, building one in-world, and that the legacy particle system is gone (migrated via adapters).

### Particle system — PhotonDust (modern; the legacy system is gone)

Two layers: **`PhotonDust.dll`** is the engine-agnostic simulation core (plain C# classes, no `Component`s, no `Sync` members — operates on flat `Span` buffers), and **`FrooxEngine.PhotonDust.*`** in `FrooxEngine.dll` is the synced `Component` wrapper layer that drives it. The old `LegacyParticleSystem`/`ParticleStyle`/legacy emitter components **no longer exist** as types — there is no `LegacyParticleSystem` in `FrooxEngine.dll`. Legacy content is migrated, not run: a swarm of `…LegacyDirectionConverter` / `LegacyGravityAdapter` / `LegacyRotationAdapter` / `LegacyTrailsRibbonAdapter` / `LegacyLightsModuleAdapter` shims + `LegacyRendererSwitcher` translate old saved data into PhotonDust modules/renderers on load. `LegacyRendererSwitcher.OnChanges` simply picks `BillboardParticleRenderer` when its `ParticleMesh` ref is null, else `MeshParticleRenderer`, and drives a `RefDrive<IParticleRenderer>` (`FrooxEngine.PhotonDust.LegacyRendererSwitcher`).

- **Simulation is CPU, multithreaded — not GPU.** Each `World` owns a `ParticleSystemManager` (`World.ParticleSystems`), whose `Update()` calls `ScheduleUpdate()` on every registered system each frame (`ParticleSystemManager.Update`). `Manager.Schedule(Action<int>, jobCount)` posts `ParticleJob`s to a TPL-Dataflow `ActionBlock` (`_processor`); the native system runs `ScheduleParallelUpdate(deltaTime, scheduler, onComplete)`, chunking work at **`PARTICLES_PER_JOB = 4096`** particles/job (`PhotonDust.ParticleSystem.PARTICLES_PER_JOB`). So sims run off the main thread and complete asynchronously via `OnSimulationComplete`. There is also a synchronous `ParticleSystem.Update(float)`.
- **Capacity / defaults.** Native ctor default `MaxParticleCount = 1024`, `ParticleSizeScale = 1f`, `ParticleOrientationOffset = floatQ.Identity`, `GlobalTransform = float4x4.Identity` (`PhotonDust.ParticleSystem..ctor`) — confirming **transforms here are single-precision `float4x4`** like the rest of the scene graph. There is a `DEFAULT_CAPACITY` static and `COLOR_PROFILE` (`ColorProfile`) on both the native and FE `ParticleSystem`. The FE component's own `Sync<int> MaxParticleCount` is clamped `MathX.Max(0, …)` and pushed into `NativeSystem.MaxParticleCount` each schedule (`FrooxEngine.PhotonDust.ParticleSystem.ScheduleUpdate`).
- **The FE `ParticleSystem` component** (`FrooxEngine.PhotonDust.ParticleSystem`) holds `Sync<int> MaxParticleCount`, `SyncRef Style` (→ `ParticleStyle`), and **`RootSpace SimulationSpace`** — the `TargetSpace` slot the sim is computed relative to; switching it `Clear()`s the native system and re-parents the renderer root, and `NativeSystem.GlobalTransform` is set to `TargetSpace.GlobalToLocal` every frame. It exposes a live `ParticleSystemFPS` (the sim runs at its own measured rate, decoupled from frame rate). Emitters self-register via `RegisterEmitter`/`UnregisterEmitter`; `AddEmitter<E>(slot)` attaches one.
- **`ParticleStyle`** (`FrooxEngine.PhotonDust.ParticleStyle`) is the reusable, shareable config: `SyncRef Renderer`, `SyncRefList Modules`, plus `UseSystemLocalScale` / `ParticleScaleMode` (`ScaleMultiplierMode`) / `UseSystemLocalRotation`. When `UseSystemLocalScale`, the system folds `Slot.LocalScaleToSpace(1f, TargetSpace)` into `ParticleSizeScale` (and rotation similarly) so the host slot's transform scales/orients particles. `AddModule<T>(root)` / `GetModule<T>(filter)`.
- **Three model objects** an emitter/module wraps: **Emitters** produce particles (`PhotonDust.ParticleEmitter.Emit(count, positions, rotations, directions, colors, sizes)` → writes into starting-data spans; `Initializes{Rotations,Lifetimes,Directions,Colors,Sizes}` flags say which it fills). Shapes: `Point/Sphere/Box/Circle/Cone/Cylinder/Line/Mesh/SkinnedMeshEmitter` (each FE emitter has `Sync Rate`, `BurstOnActivated{Min,Max}`, `BurstOnStart`, `SyncRef System`; `RequiresContinuousUpdates`, `ShouldBeEmitting`). **Modules** (`PhotonDust.ParticleModule`, abstract `SimulateChunk(offset,count,deltaTime)`) are the per-particle pipeline: initializers (`*ConstantInitializer`/`*RangeInitializer` for lifetime/color/size/speed/rotation/angular-velocity), simulators (`PositionSimulatorModule`, `RotationSimulatorModule`), forces (`GravityForce`, `LinearForce`, `RadialForce`, `SimplexTurbulentForce`, `VelocityDrag`, `Texture3D_Force`), and over-lifetime/by-velocity modifiers (`ColorOverLifetime*`, `SizeOverLifetime*`, `SizeMultiplierByVelocity`, `TextureSheetAnimator`, etc.). **Renderers** turn the buffers into geometry.
- **Module ordering & render-data dependency tracking** (`PhotonDust.ParticleSystem.EnsureValidModuleData`): modules are `Sort()`ed (each is `IComparable` via `OrderOffset`); for duplicate types only the first is active unless `AllowMultipleInstances`. Data flow is tracked with the `[Flags] RenderDataType { Position, Rotation, Size, Color, FrameIndex }` enum — each module declares `ConsumesRenderData` / `ComputesRenderData`, and the system computes each module's `FirstRenderDataConsumer` and a system-wide `modulesComputedRenderData`. `HasModuleAfter` / `HasConsumerAfter` / `HasProducerAfter` query the ordered pipeline. Modules can also declare an `InitDependencyModule` (topologically resolved into `modulesByParticleInitOrder`; unresolved ones log `"Unresolved dependencies: …"`). `FrameIndex` data is only allocated if some module computes it (`HasFrameIndexes` / `FrameGridSize`, set by `SetTileGridSize` for texture-sheet animation).
- **Renderers implement `IParticleRenderer`** (`FrooxEngine.PhotonDust.IParticleRenderer`: `Slot SetupVisuals(manager)`, `Unregister(manager)`, `UpdateVisuals(manager, onSubmitted)`). Concrete: **`BillboardParticleRenderer`** (camera-facing quads — the default), **`MeshParticleRenderer`** (`AssetRef<Material> Material`, `AssetRef<Mesh> Mesh`, `Sync Alignment` — instances a mesh per particle), **`PointCloudParticleRenderer`**, **`DebugQuadMeshRenderer`**, **`NullParticleRenderer`**, plus `TrailRendererModule` and `ParticleLightsModule` (`AngleMultiplier`). So **material/mesh attach to the renderer component, not to the system or style**; the system spawns a `_rendererRoot` slot parented under `TargetSpace` to hold the generated visuals.
- **Trails & ribbons** are full subsystems: `ParticleTrailsModule` / `TrailRendererModule` (`Trail*Initializer` for width/lifetime/color, `TrailDataManager`, `TrailLifetimeFromSizeInitializer`) and `ParticleRibbonsModule` (`Ribbon*Initializer`, `RibbonSplitterModule`, `SequenceRibbonSplitter`, `TimeProximityRibbonSplitter`). **Sub-emitters** (particles spawning particles) exist via `ParticleBirthSubEmitter` / `ParticleDeathSubEmitter` / `ParticleLifetimeSubEmitter` + `SubEmissionManager` / `SubEmissionBuffer` (`PositionSimulatorSubEmissionParameters.VelocityInheritanceMode`).
- **Building one in-world.** `Slot.SetupParticleSystem<M>(singleSlot, setupEmitter, setupRotation, setupGravity)` (extension in `FrooxEngine.PhotonDust.ParticleSystemHelper`) is the canonical builder: it creates the system + `ParticleStyle`, then adds `LifetimeRangeInitializer`, `ColorRangeInitializer`, `UniformSizeRangeInitializer`, `SpeedRangeInitializer` (under an `"Initializers"` slot), `PositionSimulatorModule` (under `"Simulators"`), optionally rotation/angular-velocity/`GravityForce`, and a `SphereEmitter` with `Rate = 10` (`SetupParticleSystem`). `DevCreateNewForm.SpawnParticleSystem(slot)` is the Dash → Create New entry. `singleSlot:true` packs everything onto one slot; otherwise initializers/simulators/emitter get child slots.
- **Inspecting live (ResoniteLink).** Look for the FE `ParticleSystem` component + a `ParticleStyle` (its `Modules` `SyncRefList` is the pipeline, `Renderer` the visuals) + one or more emitter components. Tunable knobs are `Sync` fields on those components (`Rate`, `MaxParticleCount`, initializer min/max, force vectors). The actual particle buffers live in the native `PhotonDust.ParticleSystem` (`NativeSystem` on the binding manager) and are **not** synced fields — you can't read individual particle positions over ResoniteLink, only the configuration. Particle counts/FPS surface as `ParticleCount` (native) and `ParticleSystemFPS` (FE).
