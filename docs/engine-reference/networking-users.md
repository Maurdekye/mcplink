# Resonite Networking, Users & Cloud

> Resonite networking, replication, users, permissions and cloud reference (ILSpy-verified) — RefID allocation/locality, the SyncController delta/full wire protocol, the lossy Streams channel (pose/audio), worlds and focus, the User component, permissions/roles/moderation, cloud variables, records.

## Networking, replication, users, permissions & cloud (source-grounded)

ILSpy-verified against `FrooxEngine.dll` / `SkyFrost.Base*.dll`. For *reading* engine source about how a session syncs state, who can do what, and how cloud-backed data flows.

### RefID allocation & locality
- A `RefID` packs `(position, user-byte)`. **Each user mints only IDs tagged with its own allocation byte**, so global uniqueness needs no central allocator (`ReferenceController.AllocateID` = `RefID.Construct(block.position++, block.user)`). Allocation runs inside a stack (≤16 deep, grows) of `AllocationBlock{user,position,nestedLevels}` pushed by `AllocationBlockBegin`; nested same-`(user,position)` blocks bump `nestedLevels`. `CheckAllocation` throws "New RefID allocations are currently blocked" in a wrong context.
- **Allocation-ID byte space**: `0`=unassigned, `255`=local (`RefID.IsLocalID` = `(id&0xFF)==255`), `1..254`=real users (`World.FindFreeUserAllocationID` scans 1..254, throws if exhausted) → **max 254 concurrent users** per session (`RefID.MAX_USERS=255`). `World.GetUserByAllocationID(byte)` maps back; `User.AllocationID==0` means not yet assigned.
- **Local-only elements are physically un-encodable.** `AddLocalSlot`/`InternalAddLocalSlot` wrap creation in `ReferenceController.LocalAllocationBlockBegin/End` so the slot+children get user=255 RefIDs; `SyncController.EncodeFullBatch` skips every `Key.IsLocalID` element and throws "Cannot encode local sync element" if one reaches the encoder. This is *why* `LocalUserSpace` never syncs.
- **Reference resolution is async**: `ReferenceController.RequestObject(refID, receiver)` fires `receiver.OnWorldElementAvailable` immediately if registered, else queues it until `RegisterReference` arrives. Duplicate registration throws a `FatalWorldException` (reports trash state + tick). `GetObjectOrThrow`/`GetObjectOrNull` are the sync lookups (throw on `RefID.Null`).
- **Removed elements go to a tick-keyed trash bin** before destruction: `World.MoveToTrash` / `TryRetrieveFromTrash(tick,RefID)` / `IsInTrash(RefID,out tick)` / `DestroyTrash(time)` — lets late deltas referencing a just-removed element resolve or be diagnosed instead of hard-failing.

### Sync wire protocol (`SyncController`)
- `MessageType` enum (9): `Delta`, `Confirmation`, `Stream`, `AsyncStream`, `FullInitialState`, `Full`, `Control`, `Ping`, `Disconnect`. Replication is **delta-by-default**; a full snapshot (`EncodeFullBatch`, `isInitialState=true`, type `FullInitialState`) is sent only to an initially-joining client. Every `SyncElement` defines **both** a full and a delta wire format (`Internal{Encode,Decode}{Full,Delta}`).
- Per tick `CollectDeltaMessages` walks sorted `_dirtySyncElements` → `EncodeDelta` into a `DeltaBatch` tagged with `(StateVersion, SyncTick, sender WorldTime)`. `World.StateVersion` (data revision) and `World.SyncTick` (cycle counter) tag every batch so receivers can order/validate; `World.GenerateDeltaSyncData` gates delta production (local worlds skip).
- **Conflict resolution is 3-state + cascading**: `SyncElement.Validate` → `MessageValidity{Valid,Conflict,Ignore}`. `ValidateDeltaMessages` also checks cross-record `ValidationGroup.Rule`s (`MustExist`, `CustomValidation`). When a group is invalidated, the requesting element **and every referenced record** are `.Invalidate()`d — conflicts cascade across related messages, not just one field.
- Only `World.IsAuthority` (the host) validates+confirms. `ApplyConfirmations(ids, confirmTime)` rolls each element's `Confirm(confirmTime)`. A delta cannot apply to a still-dirty element — `DecodeDelta` throws "Cannot apply delta update to a dirty sync element!" if `IsSyncDirty`.
- **Streams** (pose/voice, unreliable): `GatherStreams` positionally encodes `IsImplicitUpdatePoint(SyncTick)` streams + an id-prefixed delta list of `IsExplicitUpdatePoint` ones. `StreamMessage.MAX_AGE_SECONDS=4` (`Reliable=false`; dropped if `StreamTime - WorldTime < -4`); compresses only when `Length>=200`. With no data, the authority still emits an empty keepalive every `MAX_STREAM_PACKET_INTERVAL=0.5s` (group `ushort.MaxValue`). `AsyncStream` bypasses tick batching — enqueued immediately.
- **Steam transport caps** (`SteamNetworkManager`): `MAX_MESSAGE_SIZE=512 KiB`, `BUFFER_SIZE=8 MiB`, send rate 16 MiB/s, `INITIAL/CONNECTED_TIMEOUT=15000ms`, `SIZE_PREFIX_LENGTH=4`, `MAX_MESSAGES=24` drained/Update; oversize messages fragment+reassemble (`NeedReassembly`); conn stats update ≤1/s.

### Worlds & focus
- One process runs **many worlds at once**, each tagged `World.WorldFocus{Background,Focused,Overlay,PrivateOverlay}`. `WorldManager` keeps one `FocusedWorld` + `OverlayWorlds`/`PrivateOverlayWorlds`; `BeginUpdate` demotes the old focus to `Background` (sets `IsPresentInWorld=false`) and the new to `Focused`. A user is "present" in the focused **and** overlay worlds simultaneously.
- **Userspace is a hard single point of failure**: `WorldManager.UpdateWorld` catches a world's `Refresh()` throw → normal world gets `EmergencyDump` + `Destroy` + red "World Crashed" panel, but if `IsUserspace()` it dumps all authority worlds and calls `Engine.RequestShutdown()`.
- **Cross-world coordinates anchor to each world's local-user root** (single-precision `float4x4`): `WorldManager.TransferMatrix(m,from,to) = to.LocalUser.Root.Slot.LocalToGlobal * (from.LocalUser.Root.Slot.GlobalToLocal * m)` (+ `TransferPoint/Direction/Rotation/Scale`).
- `Userspace` (static) is the world-lifecycle API: `StartLocal/StartSession/JoinSession/EndSession/LeaveSession/OpenWorld/FocusWorld/ExitWorld`, `LocalHome/CloudHome`, `CreateHome(OwnerType,…)`, `ShouldSave/CanSave(world)`, `HasFocus`. Local home = `OwnerType.Machine` + RecordId `R-Home`; static toggles `KioskMode`, `ForceLANOnly`, field `USER_DISCONNECT_TIMEOUT`.

### User component
- `User : Worker`. Identity/network state are replicated `Sync<>` fields: `UserID`, `UserSessionId`, `MachineID`, `AllocationID`, `Platform`, `HeadDevice`, `Primaryhand`, `VR_Active`, `IsPresentInWorld/InHeadset`, `IsHost`, `IsLocalUser`, `IsPatron`, `EditMode`, `KioskMode`. **Another user's live net stats are readable straight off their `User`**: `Ping`, `FPS`, `PacketLoss`, `Download/UploadSpeed`, `QueuedMessages`, plus an open `networkStats` SyncDictionary (`GetNetworkStatistic<T>(name)`). `Role` is `ReadOnlyRef<PermissionSet>`; `UniqueIds` enumerates all of a user's ids (used for silence/block matching); avatar protection via `AvatarAccessKey`.
- `[SyncMethod]` is a networked-call marker (class is `FrooxEngine.SyncMethod`, not `…Attribute`) carrying `{Type MethodType; IReadOnlyList<string> GenericMapping}`. Only `Worker` sync-methods are network-dispatchable — fire one via the `Delegate` from `Worker.GetSyncMethod(index|name)` (`SyncMethodCount`, `GetSyncMethodData(out SyncMethodInfo, out Delegate)`, parallel `Static*` set). This is why a `Button.Pressed` (synced) needs a method on a `Worker`.
- **Respawn is ignored unless avatarless**: `RespawnRequest_OnValueChange` calls `World.RequestSpawn(this)` only if `Root == null`, then resets the flag.
- `UserRoot` exposes a full skeletal-pose API: global+`Local*` getters for head/view/neck/hips and per-side hand/controller/foot/hip/shoulder/upperarm/knee/elbow pos+rot, `GlobalScale/LocalScale`, `PlayerBounds`, `GetHandSlot(Chirality)`/`GetControllerSlot`/`HeadSlot`. `SetUserScale(scale,time)` animates (cancellable). `GetNeckOffset()` = `DEFAULT_NECK_OFFSET` unless a higher-`NeckOffsetPriority` `INeckOffsetSource` overrides.
- **Focus** is single-target per user: `user.Focus(focusable)` lazily attaches a `FocusManager` whose `Focus:IFocusable` (`_currentFocus` SyncRef) holds the one target; `FocusManagerExtensions.GetFocusingUser` scans `World.AllUsers`.
- **Panic / world-exit gesture** (`InteractionHandler.HoldMenu`, in UserspaceWorld): hold both tools' Menu near head, `Side==Left`, for `PANIC_HOLD_SECONDS=2` (haptics at 0.8/1.2/1.6s) → with Grab held destroy local UserRoots; elif on LocalHome `ExitApp`; else `ExitWorld`. Userspace open = `_userspaceOpenCharge += Delta*2` (0.5s).

### Permissions, roles & moderation
- **Role rank = index in `PermissionController.Roles`** (`SyncList<PermissionSet>`); `PermissionSet.Compare` is `Roles.IndexOf(a).CompareTo(IndexOf(b))` (implements `op_>` etc.). A role only knows its rank within its own world.
- Five well-known roles: `DefaultAnonymousRole / DefaultVisitorRole / DefaultContactRole / DefaultHostRole / DefaultOwnerRole` (+ `HighestRole/LowestRole`). Per-userID overrides in `DefaultUserPermissions` (`SyncRefDictionary<string,PermissionSet>`); `AddRole(name,desc)` just appends (no reserved-name handling).
- **Join-time role** (`GetDefaultRole`): host → `DefaultOwnerRole` if world savable/new else `DefaultHostRole`; guest → host's Role if same UserID, else `DefaultUserPermissions[userID]`, else `DefaultContactRole` if a cloud contact, else (if `DefaultSpectator`) the *last* role, else `DefaultVisitorRole`; null userID → `DefaultAnonymousRole`. **All assignments capped to the host's own role** via `FilterRole` (`min(HostUser.Role, target)`) — a guest can never outrank the host. A session can auto-assign from a cloud var: `ProcessJoinRequest` reads `DefaultRoleCloudVariable` per UserID → `connection.RoleOverride`.
- **Illegal role change = temp-ban + kick** (`User.Role_OnTargetChange`, authority-side): a non-host change is rejected if changer==target, sets null, sets a role `> changer.Role`, or the previous role outranked the changer → ForceWrite old role back, `BanManager.TempBanUser(userID)` + `TempBanUser(machineID)`, then `Kick()`. Host/local-authoritative writes bypass.
- Per-action flags on `UserPermissions` (`Sync<bool>`): `AllowEnableEditMode/Respawn/Silence/Kick/Ban/AssignRoles/SeeOtherRoles`; checked via `user.CheckPermission(...)` (extension `CanKick/CanBan/…`). **Host short-circuits Silence/Kick/Ban/AssignRoles to true, but NOT EditMode/Respawn/SeeOtherRoles.** `PermissionSet` also holds `Global/InstanceChangeValidators` (`AddGlobal/AddInstance(IWorkerPermissions,…)`, resolved by worker `Type`) — the extensible enforcement layer; `UserPermissions.DefaultViolationAction:PermissionViolationAction`, `ValidatesType(Type)` gates applicability.
- `Kick`/`Ban` are validated sync-field writes (throw "Cannot Kick the Host" / "Don't have permission…"), not direct disconnects. `Kick(KickAndRevokeInvite)` (default) → `KickRequest_OnValueChange` calls `World.RemoveAllowedUser(UserID)` (world keeps `_allowedUsers` HashSet) then `Session.Connections.GetConnection(this)?.Close()`.
- **Silence** follows all of a user's `UniqueIds`: `User.silence` toggles `PermissionController.AddSilenced/RemoveSilenced`; `IsSilenced(user)` = any UniqueId in `silencedUsers`.
- **Blocking** drives three local flags (`User.UpdateBlocking`): mutual-block or being-blocked sets `IsAudio/Rendering/CollisionLocallyBlocked` all true (and auto-adds the other to `LocalUser.blockUsers`); avatar-block sets only `IsRenderingLocallyBlocked` + spawns a proxy avatar. If the other blocks you and you're host → `Kick()` them.
- **Two moderation layers**: client-side static `FrooxEngine.BanManager` (keyed by `UserFingerprint`: `BlockAvatar/MutuallyBlock/RemoveBlock`, per-world `Ban(fingerprint, RecordId)/IsBanned`, in-memory `TempBanUser/TempBanConnection/IsTempBanned`) is **separate** from cloud-level `SkyFrost.Base.ModerationManager` (`IsPublicBanned`, `UserPublicBanned/UserMuteBanned/UserSpectatorBanned` + events).
- `SessionAccessLevel` (`SkyFrost.Base`) is an **integer-ordered** enum compared with `>=`/`<=` (`MatchesSessionAccessLevel` filters min≤level≤max). Verified members `Private`, `LAN` (`Userspace.GetHomeAccessLevel` → Private for Machine homes / non-LAN, else LAN); locale keys `World.AccessLevel.<member>`. (Live game also has Contacts/ContactsPlus/RegisteredUsers/Anyone.)
- `World` holds a **named-singleton key registry** for cross-user coordination: `RequestKey(component,key,version,onlyFree)` (steals unless `onlyFree` and already owned; versions only increase = last-writer-wins by version), `KeyOwner(key)`, `KeyVersion(key)`, `IsKeyInUse`, `GetLocalRegisteredComponent<T>(key)`.

### Cloud variables, records & gating
- **Path grammar** (`CloudVariableHelper.SplitPath`): `ownerId.subpath`, split on the **first** `.`; owner must be `OwnerType.User` (`U-`) or `Group` (`G-`) — **`Machine` (`M-`) is not a valid definition owner**. Separator can't be index 0 or last char. Subpath chars (`PreprocessPath`) restricted to **ASCII alnum + `.` `-` `_` only** (no spaces, symbols, or >0x7F).
- **A typed, permissioned definition must exist before any write**: `CloudVariableProxy.SetValue` returns false if `_definition==null` or value fails `IsValidValue`. `CloudVariableDefinition` = `{DefinitionOwnerId, Subpath, VariableType, DefaultValue, Read/Write/ListPermissions}`.
- Permission vocabulary (11 tokens): `anyone`, `variable_owner[_unsafe]`, `variable_owner_only_contacts[_unsafe]`, `definition_owner[_unsafe]`, `definition_owner_only_contacts[_unsafe]`, `definition_owner_only[_unsafe]`. `AllowsPublicAccess` = `anyone` or ends `_unsafe`. **List** perms limited to `anyone`/`definition_owner[_unsafe]`. Group-owned vars can't use any `only_contacts` perm.
- **Footgun: private cloud vars only work in Userspace.** `CloudVariableBase.CanRead` = `Proxy.PublicRead || World.IsUserspace()`; `CanWrite` = `Proxy.PublicWrite || (Proxy.PrivateWrite && World.IsUserspace())`. Non-public vars are unreadable/unwritable from a shared session world.
- Throttling (`CloudVariableProxy`): `WRITE_DELAY_SECONDS=30` (rapid writes coalesced — `WriteToCloud` skips if <30s since last; `ForceWriteToCloud()` bypasses), `REFRESH_INTERVAL_SECONDS=300` (re-read), `UNREGISTER_DELAY_SECONDS=300` (auto-unregister after losing listeners). State: `Uninitialized→ReadFromTheCloud→ChangedLocally→WrittenToCloud` (+`Invalid`,`Unregistered`).
- **Drive a field from a cloud var**: `field.SyncWithCloudVariable(path, writeBack)` attaches a `CloudValueVariableDriver` (`FieldDrive Target`, `WriteBack`, `FallbackValue`, `OverrideOwner`) that *drives* the field; `field.SyncWithCloudVariableNonDriving(path)` attaches a `CloudValueField` (`RelayRef Target`) that syncs without driving.
- **World-level join gating via cloud vars** (`World` fields): `AllowUserCloudVariable`, `DenyUserCloudVariable`, `RequiredUserJoinCloudVariable` (+ `…DenyMessage`) require/allow/deny join by a per-user cloud var value.
- **Records**: `RecordManager.CanModify(ownerId)` — `M-`→always, `U-`→only own id, `G-`→only if current user is a group member. `FetchRecord(Uri)` tries `ExtractRecordID` then falls back to `ExtractRecordPath` (cached in `recordPathTranslationCache`); `FetchRecord(ownerId, recordId, maxCachedAge?)`. Record fields: `Name/Description/AssetURI/ThumbnailURI/Tags/Path/RecordType/IsPublic/IsListed/IsForPatrons/IsReadOnly/Visits/Rating/Manifest`, plus `RecordVersion` with `IncrementGlobalVersion`/`IncrementLocalVersion(machineId,userId)`. Note two distinct `Record` types: engine-side `FrooxEngine.Store.Record` vs cloud model `SkyFrost.Base.Record`.

### Streams — the lossy/unreliable replication channel (vs SyncController delta sync)

Streams are a **separate, unreliable, grouped, per-user** replication path from the reliable component delta/full sync. They carry **avatar pose, audio, eye/mouth/finger tracking, input-device state** — anything high-rate that can tolerate drops. They live on `User`, not in the slot/component tree, and are **not the SyncController delta system** (`User.GeneratedStreamMessages` vs `GeneratedDeltaMessages` are tracked separately).

- **Why a value is "not synced normally":** a `ValueStream`/`*Stream` is a `Stream` (`FrooxEngine.Stream : ...`) owned by one `User`, addressed by `RefID`, added via `User.AddStream<S>()` / `GetStreamOrAdd(name, init)` and enumerated via `User.Streams` / `User.StreamCount`. Only the **owner** writes (`Stream.IsOwnedByLocalUser`, `CheckOwnership`); remote clients only decode. `User.ReceiveStreams` gates whether a remote user's streams are processed at all. So stream-backed fields don't appear as normal driven SyncFields and won't show component-sync traffic.
- **Transport is fire-and-forget and time-stamped** (`StreamMessage`): `Reliable => false`, `ShouldCompress => memoryStream.Length >= 200` (bytes), `SyncMessageType` = `MessageType.Stream` or `.AsyncStream`. Each message carries `UserID`, `StreamStateVersion`, `StreamTime` (double, sender world time), and `StreamGroup` (ushort). **Stale-drop:** `MAX_AGE_SECONDS = 4f` and `IsOutdated => SecondsSinceReceived >= 4f` — a stream packet older than 4 s is discarded, so a frozen/last-known stream value goes invalid rather than sticking forever. UserID/version are `Write7BitEncoded`; payload length-prefixed (`StreamMessage.EncodeData/DecodeData`).
- **Grouping & rate (`StreamGroup`/`StreamGroupManager`):** streams are bucketed by string `Group` → `ushort GroupIndex` (`StreamGroupManager.GetGroupIndex`, `AssignToGroup`); all streams in a group are batched into one `StreamMessage`. Reconfiguring groups/streams bumps `User.StreamConfigurationVersion` (`NotifyStreamConfigurationChanged`, `StreamGroup.LastConfigurationVersion`, `StreamMessage.StreamStateVersion`) so receivers can resync layout. `StreamGroupManager` is the per-user owner of `Groups`.
- **Update-point semantics (when a stream actually transmits):** `IStream.IsImplicitUpdatePoint(timePoint)` / `IsExplicitUpdatePoint(timePoint)`. For implicit streams (`ImplicitStream : Stream`, base of all `ValueStream`s) emission is **periodic by tick**: `IsImplicitUpdatePoint => IsImplicit && (timePoint - Phase) % Period == 0` (`Stream.IsImplicitUpdatePoint`). `Period`/`Phase` set via `ImplicitStream.SetUpdatePeriod(period, phase)`; a one-shot `ForceUpdate()` sets `_forceUpdatePoint`, which only fires through `IsExplicitUpdatePoint` (and is suppressed on a tick that's already an implicit point). So a `Period`-throttled pose/value stream literally only sends every N ticks — raising `Period` is the knob behind "this value updates choppily over the network."
- **Value stream types & quantization (`ValueStreamBase<T> : ImplicitStream`, concrete `ValueStream<T>`):** generic typed streams for `float3`, `floatQ`, `float`, `string`, etc. (`MultiValueStream` for arrays; buffer streams `FloatBufferStream`/`IntBufferStream`/… for sample arrays; `ReferenceStream` for `IWorldElement` refs). Per-stream `Encoding` (`ValueEncoding` enum: `Full`, `Quantized`, `Delta`) plus `FullFrameBits` (default **10**), `DeltaFrameBits` (default **8**), and `FullFrameMin/Max`, `DeltaFrameMin/Max` ranges (`ValueStreamBase.OnInit`). Encoding path (`ValueStream<T>.EncodeFrame/DecodeFrame`): `Full` → `Coder<T>.Encode` (lossless); `Quantized` → `Coder<T>.EncodeQuantized(value, FullFrameMin, FullFrameMax, FullFrameBits, …)` — i.e. value snapped to `FullFrameBits` resolution across `[Min,Max]`. **Footgun:** `ValueStream<T>` handles only `Full`/`Quantized` — selecting `Delta` (or any unhandled case) decodes to `default(T)`, and `string` throws if set to anything but `Full`. So a `Quantized` pose stream with a too-wide range or low bit count = visible positional banding/jitter.
- **Interpolation / smoothing (the "why is this laggy/smoothed" answer):** `ValueStreamBase.SetInterpolation()` turns on `IsInterpolated` and sets `InterpolationOffset = 0.05f` (**50 ms playback delay buffer**). When interpolated, decoded frames are queued with their `StreamTime` into `timePoints`/`dataPoints`; `Update()` advances a local clock (`trailingTime`/`leadingTime`, `timeTransition`) ~50 ms behind the newest received time and `SetPoint`/`Interpolate(a,b,lerp)` (via `Coder<T>.Lerp`) blends between bracketing frames. Out-of-order frames (`StreamTime < last`) are decoded-and-discarded. Owner-local streams skip interpolation entirely (`IsOwnedByLocalUser` early-out). **This 50 ms offset plus the lerp is the deliberate smoothing** behind remote avatars looking slightly delayed/eased rather than instantaneous. `Flush()` collapses the buffer to the latest frame (kills the smoothing delay).
- **Avatar pose replication (`TransformStreamDriver`):** drives a slot's `Position`/`Rotation`/`Scale` `FieldDrive`s from `PositionStream`/`RotationStream`/`ScaleStream` (`ValueStream<float3>`/`<floatQ>`/`<float3>`) plus a `RootSpaceStream` (`ReferenceStream` of the space slot). Owner-side `UpdateStreams()` writes local TRS converted into the chosen space (`parent.LocalPointToSpace`/`LocalRotationToSpace`/`LocalScaleToSpace`), subtracting `AllowOffsets` deltas; rotation is `FastNormalized` + `MathX.FilterInvalid`. Can run `RunBeforePhysics`. So an avatar's pose is **N independent quantized+interpolated streams in a group**, not component sync — explaining smoothing, the ~50 ms remote lag, and quantization banding, all independent of normal SyncField traffic.
- **Audio replication (`AudioStream<S> : Stream`, `OpusStream`/`EncodedAudioStream`/`RawBufferStream`, `AudioStreamController`):** audio is a `Stream` (has its own `Period`/`Phase`, `Active`) carrying codec frames through a `CircularAudioBuffer` (`AudioStream.Write(samples)` owner-side, `Read(buffer, AudioSimulator)` consumer-side). Jitter handling is the audio analog of pose interpolation: `MinimumBufferDelay`/`BufferSize`/`TargetBufferSize` with `UnreadSamples`/`MissedSamples` counters (`AverageRead/Write/CodecSamplesPerSecond`) — underrun shows up as `MissedSamples`. `AudioStreamController` wraps a stream + `AudioOutput` with broadcast / play-for-owner toggles; `UserAudioStream`/`AudioStreamSpawner` set up per-user voice. Voice is gated by `User.VoiceMode`/`ActiveVoiceMode`/`IsSilenced`, not by component permissions.
- **Decode-context hook:** `SyncController.CurrentlyDecodingStream` (an `IStream`) is set while a stream message is being applied — useful when reading source to tell stream-decode writes apart from normal delta application.
- **Async path:** large/expensive streams can encode/decode off-thread (`Stream.AsyncEncode`/`AsyncDecodeAndDispose`, `InternalAsyncEncode/Decode`, `TriggerAsyncEncode`, `SequenceAsyncDecodes`; `StreamMessage.IsAsynchronous` → `MessageType.AsyncStream`), processed via a TPL-Dataflow `ActionBlock`. `DummyAsyncStream` is the test/no-op variant.
- **Persistence:** streams are runtime-only replication state — `Stream.IsPersistent` is false-by-default; they reset on session end and IDs are session-scoped like everything else.
